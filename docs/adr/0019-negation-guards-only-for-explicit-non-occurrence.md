# ADR-0019: 부정 억제는 명시적 비발생 형태로 한정하고 안을 배제

- 원본: [Notion](https://app.notion.com/p/3bf499bdd6338059bf29f8d707dc20ef)

## Context

응급 룰북은 트리거 문자열이 입력에 포함되면 hard-stop 한다. 환자가 증상이 없다고 보고하는 문장도 트리거를 포함하므로 함께 차단된다. 탐침 결과 오탐 13건이 이 원인으로 확인됐고 RISK-01, RISK-04, RISK-05, RISK-06, RISK-07, RISK-08, RISK-09에 걸쳐 있었다.

- `고름은 없어요`
- `진물이 나지 않아요`
- `심하게 붓지는 않았어요`
- `눈 통증은 없어요`
- `말이 어눌하지는 않아요`

이 문장들은 환자가 위험 신호를 선제적으로 배제해 보고하는 형태이며 RAG가 답해야 하는 문의다.

그러나 부정 표현을 일괄 억제하면 반대 방향의 사고가 발생한다. 한국어에서 트리거 뒤의 `안`은 증상이 지속된다는 뜻이다.

| 입력 | 의미 | 판정 |
|---|---|---|
| 열이 안 떨어져요 | 발열 지속 | 응급 |
| 피가 안 멈춰요 | 출혈 지속 | 응급 |
| 눈이 안 보여요 | 시야 상실 | 응급 |
| 고름은 없어요 | 증상 부재 | 정상 |
| 진물이 나지 않아요 | 증상 부재 | 정상 |

즉 부정 억제는 오탐을 줄이는 동시에 미탐을 만들 수 있는 양방향 위험을 가진다.

## Decision

부정 억제를 룰북에 `negation_guards` 블록으로 선언하고 다음 세 가지 제약을 둔다.

억제 대상은 명시적 비발생 형태로 한정한다. `없`, `않`, `아니` 형태소만 사용하고 부정어 `안`은 억제 토큰으로 사용하지 않는다.

억제 규칙은 매칭된 span 직후 remainder에 앵커링해 평가한다. 문장 어디에나 있는 부정을 탐색하지 않는다.

한 룰의 트리거가 여러 번 출현하면 모든 출현을 검사하고, 억제되지 않은 출현이 하나라도 있으면 hard-stop 한다.

## Rationale

`안`을 억제 토큰에 넣으면 발열 지속, 출혈 지속, 시야 상실 세 건이 모두 미탐된다. 오탐은 보수적 실패이지만 미탐은 그렇지 않으므로 이 비대칭을 계약에 못박는다. `않`과 `아니`는 `안`과 다른 문자이므로 형태소 단위로 구별할 수 있다.

앵커링이 필요한 이유는 문장 뒤쪽의 부정이 다른 대상에 붙을 수 있기 때문이다. `고름이 나오고 통증은 없어요`에서 `없`은 통증에 붙은 것이며, 앵커링 없이 탐색하면 고름 트리거가 취소되어 실제 감염 신호가 사라진다.

모든 출현을 검사하는 이유는 첫 출현이 부정되어도 뒤에 긍정 출현이 올 수 있기 때문이다. `고름은 없지만 다른 곳에서 고름이 나와요`는 hard-stop 되어야 한다.

## Options Considered

- 부정 처리를 하지 않음: 오탐 13건이 유지되어 정상 문의가 계속 차단되므로 채택하지 않았다.
- 부정어 `안`을 포함한 일반 억제: 오탐은 줄지만 발열 지속과 출혈 지속을 미탐한다. 안전 방향이 반대이므로 채택하지 않았다.
- 부정 구문 분석기 도입: 정확도는 높아지지만 hard-stop 계층에 형태소 분석 의존성이 추가되고 결정성이 떨어진다. ADR-0017의 계층 원칙과 맞지 않아 채택하지 않았다.
- 명시적 비발생 형태로 한정한 앵커링 억제: 선언적이고 검증 가능하며 미탐 위험을 통제할 수 있어 채택했다.

## Consequences

복합 부정은 억제되지 않는다. `고름이나 악취는 없습니다`는 첫 트리거 `고름`의 remainder가 `이나악취는없습니다`이므로 앵커링된 규칙에 걸리지 않고 hard-stop 된다. 보수적 실패 방향이므로 허용하고 룰북의 `known_limitations`에 기록했다.

억제 규칙을 넓히려는 향후 변경은 `negation_true_positive` 케이스에서 실패한다. 오탐을 줄이려고 억제를 확장하는 순간 미탐이 드러나는 구조다.

## Implementation

- `rag_rulebook/rules/emergency_rules.json`에 `negation_guards` 블록을 추가하고 4개 규칙을 선언했다. `safety_note`에 `안`을 사용하지 않는 이유를 기록했다.
- `rag_rulebook/tools/emergency_matcher.py`에 `is_negated`를 구현했다. `search`를 사용해 앵커링 책임이 룰북의 `^`에 있도록 했고, `_keyword_hit`이 모든 출현을 스캔한다.
- `rag_rulebook/tools/validate_emergency_rules.py`가 세 가지를 검사한다. 억제 규칙이 컴파일되는지, `^`로 앵커링됐는지, 문자 `안`을 포함하지 않는지 확인한다.
- 회귀 스위트에 `negation_false_positive` 13건과 `negation_true_positive` 8건을 고정했다.
- 뮤테이션 검증으로 스위트가 공허하지 않음을 확인했다. 억제 규칙 제거는 `NG-01`부터 `NG-13`까지, `안` 추가는 `NT-07`, 앵커 제거는 `NT-06`에서 각각 탐지된다.
