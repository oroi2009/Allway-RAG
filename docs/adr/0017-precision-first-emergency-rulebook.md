# ADR-0017: 응급 룰북은 정확도를 우선하고 재현율은 답변 가드레일이 담당

- 원본: [Notion](https://app.notion.com/p/3bf499bdd63380dbb1e6e9cc1bdb48d6)

## Context

응급 룰북은 RAG 검색과 생성보다 먼저 실행되는 hard-stop 계층이다. 룰을 넓히면 더 많은 위험 표현을 잡을 수 있지만, 정상 문의까지 차단해 RAG 검색이 아예 실행되지 않는다.

`2026-08-15-mvp-rules-v2` 룰북의 9개 룰을 전수 탐침한 결과 오탐 21건이 확인됐다. 다음 세 건은 모두 hard-stop 되어 응급실 안내로 종결됐다.

- `약을 먹고 열이 내렸어요`
- `회복시기가 언제쯤인지 궁금해요`
- `발목이 붓어서 걷기 불편해요`

세 건 모두 정상 사후관리 문의이며 RAG가 답해야 하는 질문이다. 오탐은 두 가지를 동시에 훼손한다. 단순 CS를 AI가 1차 방어해 병원 인건비를 줄인다는 비즈니스 명분이 무너지고, 환자가 응급실 안내를 반복 수신하면 안내 자체를 신뢰하지 않게 된다.

한편 룰북으로 모든 위험 표현을 열거하는 것은 불가능하다. 이미지에만 드러나는 위험, 완곡 표현, 오타, 비한국어 입력은 텍스트 트리거로 포착되지 않는다.

## Decision

응급 룰북은 재현율이 아니라 정확도를 최적화한다. 이론의 여지가 없는 위험 표현만 hard-stop 하고 위험 카테고리를 무리하게 확장하지 않는다.

룰북이 놓친 위험 신호는 답변 생성 단계의 가드레일이 담당한다. 생성 모델이 검색 근거를 받아 답변할 때 새로운 위험 신호를 발견하면 일반 사후관리로 마무리하지 않고 병원 또는 응급실 확인을 권한다.

안전 책임은 세 계층으로 나눈다.

| 계층 | 담당 | 최적화 목표 |
|---|---|---|
| 응급 룰북 | 이론의 여지 없는 위험 | 정확도 |
| 답변 가드레일 | 생성 중 발견한 새 위험 신호 | 재현율 |
| 근거 부족 종료 | 검색 실패 및 임계값 미달 | 확실성 |

## Rationale

룰북의 가치는 포괄성이 아니라 결정성이다. 명확한 룰셋 개입으로 의료법 리스크를 피하고 책임 소재를 분명히 한다는 것이 룰북 도입의 원래 명분이며, 이는 판정이 감사 가능하고 재현 가능할 때만 성립한다. 생성 모델이 판단하면 왜 그렇게 답했는지 설명할 수 없지만 룰북은 `RISK-02가 열이 펄펄로 매칭됨`이라고 로그에 남는다.

룰북을 넓혀 재현율을 올리면 이 결정성이 흐려지고 오탐이 늘어난다. 반대로 좁게 유지하면 놓치는 위험이 생기지만, 그것은 검색 근거를 이미 확보한 답변 단계에서 더 풍부한 문맥으로 판단할 수 있다.

## Options Considered

- 룰북 확장으로 재현율 확보: 위험 표현을 계속 추가하는 방식이다. 오탐이 함께 증가해 비용 절감 명분과 상충하고, 넓은 단어 하나를 트리거로 넣는 순간 정상 문의가 대량 차단되므로 채택하지 않았다.
- 사전 LLM 분류기로 위험 판정: 재현율은 오르지만 hard-stop이 모델 판단에 의존해 결정성과 감사 가능성을 잃는다. ADR-0015의 사전 triage classifier를 확장하는 방향이기도 해 채택하지 않았다.
- 정확도 우선 룰북과 답변 가드레일 분담: 각 계층이 서로 다른 실패 방향을 갖도록 설계할 수 있어 채택했다. 룰북이 놓쳐도 답변이 받고, 답변이 애매하면 보수 안내로 종결된다.

## Consequences

룰북 단독으로는 위험을 모두 포착하지 못한다. 답변 가드레일이 구현되기 전까지는 룰북을 좁힌 만큼이 그대로 노출된다. 현재 가드레일은 미구현 상태이므로 이 결정은 답변 생성 단계 구현과 함께 완결된다.

룰북 변경 시 판단 기준이 명확해진다. 재현율을 높이는 변경은 정확도 손실을 정당화해야 하고, 정상 문의 차단이 발생하면 그 변경은 되돌린다.

## Implementation

- `rag_rulebook/rules/emergency_rules.json` 위험 카테고리를 9개로 유지했다. v3에서 카테고리를 추가하지 않았다.
- `rag_rulebook/test_cases/emergency_rule_regression.json`에 `benign_aftercare` 7건과 `word_boundary_false_positive` 10건을 추가해 정상 문의가 차단되지 않는지 고정했다.
- 답변 가드레일은 미구현이다. 답변 생성 단계 작업에서 구현한다.
